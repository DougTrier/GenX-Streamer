# Automatic program guide updates

> Public copy. Evidence paths (`artifacts/...`) and linked internal reports are kept in the project's private archive; the measurements and decisions are summarised here.

Advanced settings offers **Update program guides automatically**. The default remains enabled. Off prevents requests triggered by channel publication and scheduled guide refresh; viewing already saved guide information and explicit manual guide refresh remain available.

Changing the option joins both actual guide owners before acknowledging persistence. A failure in one suspension does not release the other owner's pending work. Settings and full-backup imports use the same gate before replacing preferences; full-backup gating occurs before enqueueing its catalog write, avoiding a capture/write dependency cycle. Nested operations retain the automatic-work gate until all operations finish. Guide preference changes invalidate stale capture identities. Shutdown joins the checkbox's actual save.

The shared schema-1 preference is an optional strict boolean named `automaticGuideUpdates`. Legacy absence means enabled in the application. SQLite migration 10→11 adds a nullable constrained metadata column: NULL preserves legacy JSON field absence, while explicit true and false round-trip. It does not rebuild the catalog projection or change checkpoint v3/candidate-manifest v1. The verified schema-10 backup is created before migration; migration does not silently replace the original records with newly defaulted JSON fields. Future unsupported schemas and failed/stale writes preserve their existing failure behavior.

## Mapped-target renewal and durable notifications (October 15, 2026)

Daily refresh is a maximum cache age, not permission to retain exhausted mapped schedules until the next day. Already published configured URL sources assess DISTINCT XMLTV IDs mapped to current, nonremoved catalog channels. Renewal is due 15 minutes before the earliest target's last known stop; a missing end is a deficit. This is a horizon assessment, not proof of continuous listings or seven-day coverage. Sources with no mapped targets keep their prior daily policy. One far-future unrelated programme cannot conceal exhausted mapped targets.

The scheduler persists a matching-descriptor attempt/publication floor of one hour. Successful builder publications also establish that hourly floor. Builder preview failures retain the existing 60-second process-local guard; restart can retry them. Explicit Find can retry an exhausted cache without enabling automatic updates. No new source or provider is authorized by this policy. Read-only not-due preflight avoids a speculative backup; real claims/publications retain source/CAS/root/permission checks and verified backups. A final claim guard rejects cancellation before COMMIT and rolls back its attempt. Later cancellation may retain an already durable attempt reservation while preventing acquisition.

A valid durable refresh receipt must notify an already open Guide even when the dialog prevents starting another acquisition. Closed, generation and abort fences still suppress obsolete notifications; the next source and timer still require automatic-work admission. The physical v10 observation retained the old-revision failure, and a held-result regression reproduces it before the notification fix.
