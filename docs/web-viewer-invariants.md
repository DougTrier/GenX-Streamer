# Web viewer invariants (hostile websites)

> Public copy. Evidence paths (`artifacts/...`) and linked internal reports are kept in the project's private archive; the measurements and decisions are summarised here.

October 18, 2026. Local's station pages and Websites tab show arbitrary websites inside GenX on Android TV (`WebPagePlugin.kt`) and Windows (`src-tauri/src/browser/web_page.rs`, a WebView2 child webview). Every page is treated as hostile: it may be written to trap the remote, take over the screen, spam prompts, exhaust memory, phish, or reach GenX itself, and a user may follow links across many such sites in a row. These invariants extend the existing registers (the original playback/catalog/sharing invariants, C01–C08 casting, G01–G08 guide); they do not renumber them.

Status: **Enforced** (implemented and verified as stated), **Partial** (implemented, with a stated residual risk), **Gap** (known, not yet closed).

## Architecture: isolation

Third-party sites never run in the WebView that hosts GenX's interface.

- **Android 11+:** each site runs in the separate `:web` process (`WebPageService`), in its own `WebView` with its own data directory, no JavaScript interface and no Tauri IPC. GenX shows it through a `SurfaceView` (`SurfaceControlViewHost`) over the viewing area and exchanges only fixed messages with it (open, place, keys, video-only, play/mute, history, status, close; back: left, a page event from a fixed list, full screen). Focusing the SurfaceView gives the page real window focus, so the TV keyboard and voice typing work in the site's own fields; the remote's pointer keys are caught at the page's container first. Pointer and on-screen bar draw in the page's process.
- **Android 7–10:** the same `PageController` runs in GenX's process (shared renderer, see W10).
- **Windows:** each site is its own WebView2 child (`web_page.rs`) with its own CoreWebView2; Chromium renders sites in separate renderer processes; the site is a remote origin and GenX's only capability is local-only. It shares GenX's browser profile (cookie store), so isolation from GenX's data rests on the same-origin policy.

## Residual risks, stated plainly

- **Android 7–10 (W10):** no separate page process there (SurfaceControlViewHost needs Android 11); a hostile page can force GenX's renderer recovery. Both test TVs run Android 14.
- **`SurfaceView.getHostToken()`** is deprecated on the newest Android SDK; it works on Android 11–14 and must be revisited when targeting a release that removes it.
- **Determined pages vs. page scripts:** where enforcement is only a page script (Android script dialogs are native; PC dialogs and fullscreen are native plus script), a page can sometimes recover the original browser functions. The native WebView settings are the guarantee; scripts are defense in depth.
- **Paid streaming DRM, sign-ins and typing on a remote** are usability limits, not security ones.

## Hostile-site test set

`tests/ui/hostile-pages.spec.ts` runs GenX's page scripts against fixture pages that each attack one invariant (dialog loops, beforeunload, fullscreen grabs, forged remote messages, hostile titles). Native enforcement (permissions, schemes, dialogs, renderer isolation) is verified on the devices with real public test pages and recorded in `docs/local-streams.md`.
