# Channel and program-guide update cadence

> Public copy. Evidence paths (`artifacts/...`) and linked internal reports are kept in the project's private archive; the measurements and decisions are summarised here.

Settings → Your sources provides **Automatic updates** with Off, Hourly, 4 times daily (every 6 hours), Daily, Weekly, Every 2 weeks and Monthly. Off is the default. This refreshes the same saved URL source, preserving its identity; it does not clone a repository or add a duplicate source. Local files require explicit reimport. Editable discovery-provider suggestions are used only by the explicit Scan workflow.

Checks run while the application is open and eligible in the foreground. Startup/resume checks due work only when enabled; Off does not acquire sources or guides automatically. One owned timer schedules the next eligible check, bounded to a day so long intervals are rechecked safely. It is not an operating-system background task, scheduled wake or guarantee that a closed app updates on time. Returning to the app checks overdue work; there is no catch-up burst for every missed interval. Background/close/disable cancels and joins owned work rather than starting hidden acquisitions. Automatic updates also wait while a channel scan is running or paused with progress that Continue can resume (October 17, 2026): refreshing a source rewrites its channels and bumps the catalog revision, which invalidates the paused scan's saved checks. Favorites, removals, category edits and settings do not affect the catalog revision. If a manual Refresh, import or source removal still changes the sources while paused, Continue explains "Your channel sources were updated after this scan paused" and keeps the channels it already saved.

The next due time is based on the last **persisted actual automatic attempt**, not the last successful response or every app restart. Hourly/6-hour/daily/weekly/2-week intervals use fixed elapsed durations. Monthly uses the next UTC calendar month at the same time, clamping the day to that month's end (January 31 → February 28, or 29 in a leap year). It is not a 30-day approximation. The shared `src/catalog/refresh-cadence.ts` and native guide scheduling use the same policy. Native guide attempt records remain keyed to the approved configuration; a successful schedule revision does not itself reset that identity.

Attempts are persisted before network work to avoid failure/restart retry storms. A failed or canceled automatic attempt consumes its configured interval; manual **Refresh** remains available. Automatic collection retains source/network/parser bounds and atomic generation/revision guards. Failure, empty or malformed guide data preserves the last committed catalog/schedule and mappings. Reconciliation preserves stable channel identities, favorites and removed-channel records; a timeout never automatically deletes a channel. Automatic guide updates use already published URL guide configurations, defer to manual previews and never import a newly discovered URL without the acquisition/publication workflow.

Preferences JSON remains schema1. Optional canonical `sourceRefreshCadence` has authority when present; a missing field migrates the existing `automaticSourceRefresh` boolean to Daily/Off. The legacy boolean is serialized as a compatibility mirror of whether cadence is enabled. Invalid explicit cadence refuses the record, rather than silently changing it. The attempt timestamp and cadence survive settings/backup round trips. Native SQLite schema8 preserves the preference and extends program category metadata; upgrade/recovery retains last-valid data.
