October 11, 2026 audit. These requirements extend the existing guide mission without renumbering G01–G08, GUIDE01 or the original playback/data/security contracts. See [architecture and gap audit](guide-architecture.md), original guide contract, [streaming invariants](streaming-invariants.md) and source collection.

Core rule: unavailable, stale, incomplete or malformed guide input cannot erase the validated working cache, corrupt mappings, break navigation or crash viewing. Provider absence cannot be fixed by invented listings. Release remains incomplete until deterministic, installed-device and sustained-resource evidence covers the required scopes.

## Cross-boundary rules

- **P02 ownership:** close/background/selection change retains and joins admitted fetch, blocking parse, SQL task, preview ticket, worker, timer and callbacks. A timeout is an unconfirmed operation, not permission to drop the owner. New work cannot bypass closing admission. Read-only diagnostics contain fixed stages/counts, no URLs or payloads.
- **P03 / D02 / D03 publication:** capture exact catalog and source revisions, check them inside the publication transaction, and report a real committed receipt truthfully even if cancellation arrives later. Never silently rebase obsolete mapping results. Preserve favorites, removals, manual category intent, settings and canonical stream identity.
- **Source collection / S03 / S06:** inspect actual response bytes; validate every network destination and redirect through existing policy, TLS and explicit HTTP admission. No extension guessing, certificate bypass, credential logs or automatic unapproved scraping. License/free access is not redistribution authority.
- **P01 / P04:** guide acquisition/query has no decoder. Stream availability and decoded Playing evidence remain separate from mapping and schedule labels. One local engine remains owned through Guide/Search/fullscreen.
- **Foreground lifecycle:** user-selected cadence authorizes only the supported foreground owner today. Off admits no automatic fetch. Saved published URL guides alone are eligible; saving a preview/config is not automatic approval. Attempts persist before acquisition, so restarts do not hammer a failing feed. Manual refresh remains explicit. Background-service scheduling would require a separately reviewed architecture and proof.
- **Fallback and confirmed intent:** retain validated cached data through provider failure; never delete an explicit mapping just because its feed temporarily lacks entries. Low-confidence candidates require user selection. Future scoring must assess the channel's real coverage, not replace a pinned mapping using aggregate popularity or count.
- **304 and time:** successful conditional reuse, once implemented, requires the exact validated prior definition/cache and temporal reassessment. A 304 is not proof that listings extend into the future. Last attempted, last successfully published, known schedule horizon and stale status must remain distinct.
- **Scope and limits:** unknown/unsupported formats and capacity limits produce actionable whole-result refusal. No truncation is reported as a complete imported guide. A filtered/subset import must declare its scope and preserve reference validity; a seven-day UI window does not create missing programs.

## Acceptance record discipline

Record each fixture seed/feed byte hash, exact source/binary/tool versions, command, terminal exit, scope, device/API/ABI/WebView, request/parse/commit/query timings, coverage interval and final resource/observer cleanup. Distinguish implemented, deterministic fixture-proved, historical installed scoped proof and still missing. Test closure cannot be inferred from code existence, issue closure, a repository commit date or a broad test count.

The source registry must classify providers Verified Active, Unverified, Stale, Unavailable or Restricted using timestamped actual responses, channel/program counts, input/expanded sizes, future schedule and license evidence. An engineering parser experiment above product limits is research only. Expired or incomplete schedules must remain labeled rather than being treated as current through a recent download timestamp.
