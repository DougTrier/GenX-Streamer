# Navigation invariants (remote, keyboard and touch)

> Public copy. Evidence paths (`artifacts/...`) and linked internal reports are kept in the project's private archive; the measurements and decisions are summarised here.

October 19, 2026. Owner request: "a full application, full surface navigation on Streamer … using only the navigation option from remote … systematically eliminate navigation issues … the final state should be a smooth and pleasant navigation experience." This register gives the remote contract in remote-navigation.md testable IDs. It extends the existing registers (the original 30 invariants, C01–C08, G01–G08, W01–W16, LX/MP) and does not renumber them. Owner requests the same day folded the Local tabs and the channel categories into one row each (NV13).

Status: **Enforced** (implemented and verified as stated), **Partial** (implemented, with a stated residual risk or missing device evidence), **Gap** (known, not yet closed).

Device evidence comes from the remote-only sweep (`nav-sweep2.mjs`, below): real Android key events (`adb shell input keyevent`), with GenX's page only observed over the WebView debugger (focus, geometry, open dialogs), never driven. Browser tests prove the same routes in Chromium with real key presses; they do not prove the device's remote mapping.

## Sweep method

`nav-sweep2.mjs <serial> <screen> <out.json> [budget] [start-keys] [scope]` walks one screen as a frontier: from the current control it tries each untried direction; when none is left it travels by known moves to the nearest control that still has one, and inside a long list it holds a direction until focus leaves the list. Every item of a list (channels, countries, Local rows, guide rows, cards) counts as one place. After every key it records the checks above and, at the end, reversibility over all recorded moves and where Back lands. `goto.mjs` reaches a named control with arrow keys only. Both observe GenX's page over the WebView debugger and never drive it. Results: `artifacts/navigation/2026-10-19/`.

The walk never presses OK while exploring; screens are opened with OK on their button after reaching it by arrows, so activation stays deliberate.
