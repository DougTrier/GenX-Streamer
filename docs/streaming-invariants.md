# GenX Streamer Streaming Reliability Invariants

> Public copy. Evidence paths (`artifacts/...`) and linked internal reports are kept in the project's private archive; the measurements and decisions are summarised here.

Research reviewed October 10, 2026. Scope: the Windows and Android player, playlist storage, and optional Windows LAN sharing server.

TMG must behave predictably when a stream fails. It cannot guarantee that an external broadcaster remains available. The implementation should keep one player owner, cancel obsolete work, preserve user data, and isolate sharing from local playback. Tauri remains a candidate until Windows and physical Android playback pass the initial compatibility gate.

An invariant is a condition the application must preserve through success, failure, cancellation, and shutdown. The numerical acceptance targets below are proposed project requirements, not performance measurements or guarantees from upstream projects. None has yet been verified in the new application.

## Playback invariants

| ID | Required condition | Acceptance test | Evidence |
| --- | --- | --- | --- |
| P01 | Each device owns at most one active local player session. Each session owns its engine, listeners, timers, abort signals, and resource handles. | Switch 500 times, including rapid A to B to C transitions. Only C can play or update the UI; earlier sessions have no live loaders or owned handles. | E01, E02; previous TMG audit |
| P02 | Disposal is idempotent and works before, during, and after initialization. | Stop twice, close during manifest loading, force a fatal error, and exit during reconnect. New media requests cease and session-owned resources are released within a proposed two-second normal-stop target. | E02 |
| P03 | Only the latest selection can attach media, change playback status, or publish a shared channel. | Delay A's response until after B succeeds. A cannot replace B, show an obsolete error, or enter history as successfully played. | Project design rule |
| P04 | UI states follow actual media progress. Manifest parsing or an HTTP 200 alone cannot mean Playing. | Serve a valid manifest with stalled segments. Show Connecting or Buffering, then a bounded error; never show Playing until video progress is observed. | E07; previous TMG silent-timeout behavior |
| P05 | Startup and recovery have deadlines, bounded retries, and immediate user cancellation. | Simulate DNS failure, stalled headers, stalled body, missing segments, and 503. Proposed budget: 20 seconds per startup/recovery episode, including at most two automatic retries. Preserve Retry and channel selection. Honor Retry-After without exceeding the episode budget. | E06; project design rule |
| P06 | Pause or background/resume cannot create duplicate sessions or retry vanished historical segments forever. | Pause beyond the available live window and resume. Recover to the live edge with a visible explanation. Repeat 50 Android background/resume cycles and verify session count. Initial Android policy pauses foreground-only playback on backgrounding; background audio is deferred. | E09 |
| P07 | Unsupported codec, access refusal, DNS failure, TLS failure, missing source, and timeout remain distinguishable. | Use controlled fixtures for each cause. Show a plain-language reason and a safe next action. Show geoblocking only when supported by source metadata or explicit evidence. | E06, E07, E11, E12 |
| P08 | Supported long-running streams have bounded buffer/cache ownership and no persistent session-resource growth. | Two-hour playback and switch soak on Windows and physical Android. Observe engine/worker/request counts plus JS and process memory. Set device-specific memory ceilings from baseline measurements; reject persistent growth after warm-up. Include HEVC only where capability tests allow it. October 22, 2026: the owner accepted P08 on observation (overnight scans, two full football games on Paid TV) and waived the two-hour soak; no two-hour measurement exists. | E01 |
| P09 | Fullscreen preserves playback and has a reliable exit route on each platform. | Enter/exit repeatedly, change channels, rotate Android, press Back/Escape, and interrupt playback. No duplicate player, lost controls, or trapped fullscreen state. Test separately in the desktop wrapper and Android APK. | E08 |

## Catalog and storage invariants

| ID | Required condition | Acceptance test | Evidence |
| --- | --- | --- | --- |
| D01 | Source refresh cannot erase favorites, preferences, or the previous valid catalog. | Refresh with changed URLs, removed entries, duplicates, malformed content, and an empty failure response. Preserve user records; keep unmatched favorites recoverable. Prefer playlist identity plus tvg-id where available, and persist fallback identities; do not use array positions or stream URLs alone as universal channel IDs. | E03 |
| D02 | Writes are serialized and commits are atomic. Recovery retains the last valid revision. | Race favorite edits with refresh; terminate the process during writing; simulate disk-full and corrupted settings. No partial JSON/database state and no lost successful edits. | E04 |
| D03 | Canceled or superseded imports cannot commit. | Cancel during download, parse, copy, validation, and persistence preparation. Deliver late worker results after cancellation. Stored catalog revision remains unchanged. If an atomic commit already happened, report completion rather than falsely acknowledging cancellation. | E05 |
| D04 | Large or malicious input has explicit limits and cannot freeze the viewing controls. | Test a 100,000-entry synthetic playlist, long lines, duplicate IDs, invalid URLs, malformed attributes, and oversized downloads. Parse off the UI thread with cancel support; virtualize the channel list. Proposed limits: 20 MiB playlist input and 100,000 entries; fail clearly above limits. Set the search-response target to 200 ms on recorded reference devices. | E05; project design rule |
| D05 | Source status is contextual and temporary. | Fail a previously working channel once and retry later. Keep its favorites and catalog entry; record last-check time and failure reason. A successful probe is not advertised as a playback guarantee. | E11 |

## Sharing and release invariants

| ID | Required condition | Acceptance test | Evidence |
| --- | --- | --- | --- |
| S01 | LAN sharing starts only on explicit action and shuts down with the owning app. Local playback works with sharing disabled. | Start/stop repeatedly, simulate port collision, change the network, and exit the app. Verify listening interfaces, process ownership, and no orphan server. No router port-forwarding or automatic firewall edits. | Project design rule |
| S02 | A connected viewer follows an explicit channel revision; stale responses cannot revert it. Local pause, client pause, and server stop are distinct operations. | Two clients join, the host changes channels, and delayed old responses arrive. Both follow the latest published revision. Local pause does not stop other viewers; stopping sharing disconnects them without stopping local playback. | E02; project design rule |
| S03 | Server resource ownership survives abrupt client disappearance. Slow clients cannot block fast clients. | Kill a client without a stop message, suspend its phone, and throttle another client. Proposed lease expiry: 30 seconds. Release unused upstream work when no local or remote consumer remains. Bound per-client queues and cache eviction; do not hold shared state locks across network I/O. | E02; project design rule |
| S04 | Pairing grants scoped viewing access and can be revoked. Secrets must not cross the network in unprotected HTTP in a production-secure sharing mode. | Reject invalid/expired pairing, brute-force attempts, revoked clients, and unauthorized control routes. Validate a usable HTTPS trust flow on native and browser clients before release. A local HTTP prototype is not accepted as encrypted sharing. | Project design rule |
| S05 | The relay accepts only server-issued media resources from admitted channel sessions. Static-file requests cannot escape the bundled UI. | Test encoded traversal, Windows separators, malformed encoding, redirects into loopback/private/link-local destinations, arbitrary target URLs, and oversized responses. Validate upstream destinations on every redirect; keep the paired LAN server distinct from permitted external stream targets. Handle HLS variants, segments, keys, initialization maps, queries, and Range requests in fixtures. | E10; previous TMG relay audit |
| S06 | Logs contain enough context to diagnose failure without exposing stream secrets. | Inject credentials into URL userinfo, path, queries, headers, and signed segment URLs. Exported diagnostics retain error category/session ID but contain none of the secrets. Use redaction before persistence. | E06 |
| R01 | Native packaging meets its stated portability contract. | Windows ZIP runs as a standard user from paths with spaces and Unicode; portable settings stay beside it when writable. Read-only media produces an explicit storage choice. Verify WebView2 presence/failure behavior. Signed Android APK starts and plays independently of the Windows host. | [Tauri WebView requirements](https://v2.tauri.app/reference/webview-versions/), [Android signing](https://developer.android.com/studio/publish/app-signing) |
| R02 | Releases have verifiable identity and test evidence. Missing required checks block the release. | Lock dependencies; record toolchain, source revision, hashes, dependency notices, signatures, supported devices, and actual scan results. Remove a required test report deliberately and confirm failure. Test Defender and the user's EDR policy without disabling protection. A reputation warning is classified separately from malware detection. | E10, E13 |

## Test strategy

### SCAN-WIN01 — Failed publication remains truthful and recoverable

A Windows scan whose save fails must stop with a visible reason and recovery action. It must preserve the last acknowledged catalog/checkpoint and never present a frozen counter as active Checking. Checked-in-memory counts are not durable progress. Cancellation of peer probes must not overwrite the publication failure; diagnostics retain bounded fixed failure records per operation without source addresses or credentials.

The native owner accepts only its exact retained observation for the original candidate, source, platform and reservation. A shared timeout, transport refusal or missing reply cannot be converted into invented committable health evidence. Unconfirmed work must remain eligible for explicit recovery without stopping unrelated candidates. A confirmed native timeout is retained as that actual observation. Stop and Exit join original work; a failed scan and an unconfirmed cleanup are distinct outcomes.

Regression acceptance: force a first-batch save refusal; prove unchanged durable revisions/counts, visible stopped/error/Continue state, retained publication cause after canceled peers, and cold recovery from the last real ACK. Mix a rejected probe with healthy channels and confirm that no invented observation reaches publication. Exercise late native timeout and cancellation, with actual owner cleanup verified independently. Windows native reproduction at64/63,529 and the controlled UI/diagnostic evidence are retained under artifacts/scan-save-failure/2026-10-14. The observed native refusal was scan-resume-commit-invalid. A strict native-echo fixture reproduced the synthetic-observation mismatch; the bounded owner now preserves actual native evidence and defers unconfirmed replies. A separate worker/bridge fixture reproduced stale origin exclusions during deferral; only actual in-flight probes now contribute exclusions. Exact Windows fac23aac advanced beyond64, persisted75 observations and34 channels, paused through actual Stop and exited ordinarily with code0. The complete63,529-channel run and adverse storage/cleanup matrix remain unverified. This supplemental contract does not alter the original thirty-invariant count or assert Android failure.

Use a local deterministic origin server for automated failures: delayed headers/body, dropped connections, 401/403/404/429/503, malformed manifests, sliding windows, redirects, byte ranges, keys/maps, and out-of-order responses. Inject clocks and seeded retry jitter so the same test produces the same sequence. Restrict synthetic-source exceptions to tests; production relay rules remain enforced.

Public IPTV streams are exploratory compatibility samples. They cannot determine CI pass/fail because their availability, location restrictions, and content change independently of our code. Maintain a small authorized sample matrix recording container, audio/video codec, device, OS/WebView version, direct-versus-relay path, and observed result.

Verify Windows and physical Android separately. Browser-only mockup tests do not establish native media, fullscreen, battery, network-policy, or packaging correctness.

## Evidence limits

The guarantees and acceptance tests above are TMG design requirements inferred from the documented failures; upstream projects did not validate them for us. They are currently planned, not implemented or passed.

The separate [Jellyfin issue 17319](https://github.com/jellyfin/jellyfin/issues/17319) proposes timeout and locking problems but was closed as not planned under the project's contribution policy. Its proposed fixes are not counted as maintainer-verified findings here. Network-lock isolation remains an independent TMG design rule with our own controlled test.
